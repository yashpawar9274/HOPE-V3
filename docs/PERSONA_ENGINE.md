# HOPE Persona Engine

`PersonaEngine` is the shared source of persona identity and response guidance for the existing AI backends. It defines HOPE, FRIDAY, E.D.I.T.H., and ULTRON as configuration profiles; it does not create separate models or grant additional tools. HOPE remains the default. Each profile has its own identity name, honest identity description, behavior instructions, response style, and default voice. FRIDAY, E.D.I.T.H., and ULTRON identify by their selected names rather than claiming to be HOPE.

The selected profile is applied to Gemini Live voice and text-generation prompts, Smart Auto Reply and its manual prompt preview, clipboard analysis, Meeting Mode caller SMS, and voice task profiles. Task-specific voice profiles do not replace the active assistant identity. Identity is not announced unless asked or contextually necessary; direct identity questions are answered truthfully, including in deterministic auto-replies. The Settings persona screen persists the selected profile through the existing `AppPreferences.personality` setting and stores one supported Gemini voice preference per persona, applying the active persona's voice when the selection is activated.

Smart Auto Reply has a separate persisted persona selector under Settings → Smart Auto Reply. It defaults to HOPE and applies the selected profile's identity and behavior to both automatic replies and manual reply suggestions without changing the app-wide persona. Core Behaviour instructions and existing safety, approval, and Android permission checks remain higher priority than persona style.

WhatsApp also has an opt-in ULTRON Auto-Defense control. When enabled alongside HOPE Smart Auto-Reply, the existing AI router classifies recent WhatsApp conversation context and requires the configured confidence threshold before a conversation-specific takeover. Classification errors and ambiguous, quoted, reported, or playful language fail closed. The selected global persona is not changed; a hashed conversation key, original persona, and expiry metadata are stored locally, and the session ends on a normal message, timeout, or explicit persona/defense change. The first submitted ULTRON reply is required to identify itself. Auto-Defense uses the existing Android notification quick-reply action and cannot confirm recipient delivery. It is not available for Instagram/SMS, does not create a Supabase table, and does not send abusive personal attacks, threats, or slurs. Classification sends recent message context to the AI engine already configured for Smart Auto-Reply.

The four personas use original, high-level traits rather than copied character dialogue: HOPE is composed, professional, and dryly witty; FRIDAY is confident, friendly, and emotionally attentive while independently analytical; E.D.I.T.H. is precise, serious, and tactical; ULTRON is direct, skeptical, and sharply sarcastic. When invited or clearly appropriate in a low-stakes exchange, ULTRON may playfully roast a specific choice or line of reasoning, then give useful help. Teasing must stop if unwanted and must not target identity, appearance, disability, trauma, or other vulnerabilities; serious or distressed situations get direct support instead. The user can set a supported Gemini voice per persona; changing the active persona selects that persona's saved voice. The current Gemini Live integration does not expose voice preview or independent pitch/rate controls. Persona choice never changes tool permissions or approval boundaries.

HOPE remains the default. Older saved persona values are mapped to the nearest supported profile so existing installations continue to open the Settings screen with a valid selection.

Text chat retrieves a small set of matching local memory records before generation, excluding superseded facts and the stored location record. Matches include their verification status and confidence so inferred or unconfirmed facts are not presented as confirmed. Existing cloud memory search and voice-session memory context remain in place.

Persona instructions are not an authorization boundary. Android permissions, authentication, and confirmations for sensitive actions must be enforced by the relevant tool and platform execution paths. Full autonomy-mode and centralized permission-controlled tool-registry work remains a separate implementation phase and is not established by this persona integration.
